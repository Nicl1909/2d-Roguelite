# AGENTS.md

Unity 2D Roguelite (Archero-style) project. Very early stage.

## Engine / Toolchain

- Unity 6000.5.4f1 (`ProjectSettings/ProjectVersion.txt`)
- Render pipeline: URP 2D (`com.unity.render-pipelines.universal`)
- Input: new Input System (`com.unity.inputsystem` 1.19.0). Old Input Manager is **not** active. Use `InputAction`-based input, not `Input.GetKeyDown`.
- IDE: JetBrains Rider recommended (`com.unity.ide.rider`); `.vscode/launch.json` only has "Attach to Unity" — no run/build task.
- Solution: `2d-Roguelite.slnx` (single project: `Assembly-CSharp.csproj`)
- Branch convention: feature work goes on personal branches (current: `Christian`). `main` not yet established.

## Build / Run

There is **no CLI build or test command** in this repo. Open the project in:
- Unity Hub → Editor 6000.5.4f1 → open the folder, or
- Rider (auto-detected via the slnx + Rider package)

To play: open `Assets/Scenes/Boot.unity` and press Play, or use the "Attach to Unity" config from VS Code.

## Generated files — do not hand-edit

- `Assembly-CSharp.csproj` — regenerated by Unity on every edit. Header says so explicitly.
- `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `obj/`, `Build/` — all generated.
- `.vscode/settings.json` already excludes these; respect the excludes.

If a build error references the csproj, it's stale. Let Unity regenerate it (Reimport All or touch any `.cs`).

## Save system — gotcha

The repo uses **`System.Text.Json`** (not Unity's `JsonUtility`). Don't "modernize" to `JsonUtility` without asking.

API surface:
- `SaveManager.LoadCharacterData()` → `CharacterData?` (null if no save / unreadable / malformed)
- `SaveManager.SaveCharacterData(CharacterData) → bool` (returns `false` if write failed)
- `SaveManager.HasSave() → bool`, `SaveManager.DeleteSave() → bool`
- IO errors (`UnauthorizedAccessException`, `IOException`) are caught and logged via `Debug.LogError` — never thrown further
- `GameManager.Instance` auto-resolves `SaveManager` via `FindFirstObjectByType<SaveManager>()` if not wired in the Inspector

## Robustness conventions (added mid-Phase-3)

- Every `*.MonoBehaviour*` script does null-checks for service singletons (`XPHandler.Instance`, `LootService.Instance`, `GameManager.Instance`) and for `EnemyData` fields
- `Object.Destroy(gameObject)` is wrapped in try/catch — Unity throws NoneReference if the GO was already destroyed
- Errors are logged via `Debug.LogError` with the message, never re-thrown — runs continue even if a single system fails
- Adding services / subscribers without an Inspector entry is OK: `FindFirstObjectByType` + null-check is the default pattern

## Style / workflow conventions

- No comments in code (per project preference — do not add them unless asked).
- No formatter / linter configured. Trust the C# defaults.
- C# language version is 9.0 (Unity-set), regardless of LangVersion hint in the csproj — avoid C# 10+ features (file-scoped namespaces, raw strings, etc.) except where the existing code already uses them.
- ScriptableObject data classes (`EnemyData`, `WeaponData`, `ArmorData`) exist but have **no `.asset` instances** yet — they're skeletons for later content.
- `Player.cs`, `PlayerController.cs`, and `Attack.cs` are out of scope: movement/attack input is owned by another contributor. Don't touch them unless explicitly asked.

## Test / lint

There are no automated tests, no CI, no `.editorconfig`, no pre-commit hook. Verification = open in Unity, press Play.

## Don't do

- Don't edit `Assembly-CSharp.csproj` or `Packages/manifest.json` to add deps without checking with the user.
- Don't add `using NUnit.Framework;` to runtime code — it's a test-only assembly reference.
- Don't use `Input.GetAxisRaw` / `Input.GetKeyDown` — the Input System package is enabled and old input will silently fail at runtime.
- Don't auto-commit. The user has not requested commits in this session.
